## Introduction

This project will entail assigning correct identities to all tracked individuals in H5 SLEAP files (generated with pandas from frame based SLEAP CSV files) for a given video replicate (1 rep = 96 total videos/h5 files). We intentionally used SLEAP in inference mode without ID tracking to have better performance/speed since we know the ROI of each individual.

Additionally, since 1 replicate contains 96 sequential hours of video, we want to do this across all 96 hours for a given video. Further, we want to concatenate all the tracking data together into a single parquet file that is sorted and ready for downstream analysis. This file can then be utilized for downstream locomotion and actigraphy analysis in python or R...

## What the Pipeline Does?

Currently, the pipeline will run through all of the files passed to it in the config.

There are paths for:
`h5_root` - This path contains the h5 files for all 96 hours of recording for all of the Diet dataset. Note: when we run this again for our wheat data we will have to pass the new directory of output. This output was generated by using sleap to inference over all video chunks and then write the output to a frame by frame csv and ultimately to a h5 file.

`roi_root` - This path contains the ROI json files grabbed by the ROItools .ipynb and scripts. It contains the regions of interest where each individual is contained.

`mortality_root` - This path contains the tsv files generated by boris that contain the mortality data. If an aphid did not die it is not in the .tsv file. If no aphids died in a video rep, then the .tsv file will be empty except for the first row of column headers.

Additionally, there is an `output` path for the output which we will keep in the working directory where this readme is contained. You can provide a different path if need be.

The video replicates that this pipeline will run across are hardcoded directly in the `replicates` variable in the config. For example:

```snakemake
replicates:
  # LD rep 1
  "agesync_7-29-25-rep1":
    treatment: "LD-Diet"
    json_file: "LD-diet_agesync_7-29-25-rep1_Camera0_20250804_122315_0-215999.json"
  
  # LD rep 2
  "agesync_8-8-25-rep2":
    treatment: "LD-Diet"
    json_file: "LD-diet_agesync_8-8-25-rep2_Camera0_20250814_125919_0-215999.json"

  # LD rep 3
  "agesync_8-19-25-rep3":
    treatment: "LD-Diet"
    json_file: "LD-diet_agesync_8-19-25-rep3_Camera0_20250825_131731_0-215999.json"
  
  # LD rep 4
  "agesync_8-25-25-rep4":
    treatment: "LD-Diet"
    json_file: "LD-diet_agesync_8-25-25-rep4_Camera0_20250901_123631_0-215999.json"

  # ... continues on for all 8 reps in LD and then for DD, etc. etc.
```

For the Snakemake pipeline, there are two rules which will point to and run two scripts in the `scripts` directory. 

The first script will run across every single h5 file and make a frame column based on the frame coordinates in the file name. It will also generate a ZT column based on the start time of the filename, and with the hardcoded value that 8am is ZT0 which is true for all files as this is when the lights in the colony are programmed. Further, it will look at the corresponding ROI json files and determine the identity of each aphid based on their x,y coordinates and reshape the data so that each aphid is sorted correctly (SLEAP will loose identity when run without track mode so our h5s currently contain the wrong identity, running without track mode saves compute and time since we can just assign ID here). These sorted and timestamped H5s containing only the xy position of the aphid abdomen are then made into parquets and saved to disc as temp files.

In the second script we take the temp files made in the previous rule and concatenate them all together. Additionally, we remove any data after an aphid has died as we don't want that positional data anymore. At the end of this step we have one file per video with all the x y data (and prediction score) for each individuals abdomen with rows for global frame and timestamps.

## Deploying with Snakemake

After we prototyped for a bit, we now have a good idea of how to run this workflow to go from H5 to sorted and concatenated parquet files that can be used in R/python etc. for downstream analysis.

We now want to run this type of an analysis on all of our 16 reps (8 in LD and 8 in DD conditions). Since this is a lot of processing, we want to use snakemake to manage all of this for obvious reasons.

While we will build this snakemake workflow inside of this directory in OneDrive. We will move it onto our C: or D: drive when its time to run. We can still point to our uv venv by activating the env that we currently have in our OneDrive folder. Additionally, we can utilize the Snakemake version installed via uv tool mentioned above.

Additionally, we can point to all of our data directories with hard coded paths in the config. To re-do this on another machine or directory, just change those paths to where the data lives...

Once we have our code copied over we can first activate our env...


Once finished we can copy this directory back into OneDrive for git tracking in our master `Rpadi_Video_Tracking_Analysis` directory and also keep it safely backed-up w/ OneDrive.

## Output
The final output of our pipeline here should be 1 master parquet file for each 96 h video. This parquet has the following column structure...

- `frame_idx` - per hour frame for that chunk --> Update: dropped, keeping only `global_frame`
- `x` - x position
- `y` - y position
- `score` - prediction score
- `individual` - 1 through 6
- `video_id` - string with video filename
- `treatment` - LD or DD
- `replicate` - video rep number
- `global_frame` - global 96h frame count
- `elapsed_hours` - hours elapsed --> Update: dropped
- `ZT_time` - ZT time, 0ZT = 8am --> Update: dropped
